This hardens the rev-light and vibration engine against a flood of telemetry
packets. It includes the pedal vibration and ACC / Le Mans Ultimate support
from [0.4.0](https://github.com/crmne/omarchy-moza/releases/tag/v0.4.0), with
no change to the panel or settings.

Download the [Linux x86-64 plugin archive](https://github.com/crmne/omarchy-moza/releases/download/v0.4.1/omarchy-moza-0.4.1.tar.gz).
The bundled executables are built twice in a pinned environment and verified
before publication. The release includes their checksums and build provenance.

![Rev lights and pedal inputs, using simulated data](https://raw.githubusercontent.com/crmne/omarchy-moza/v0.4.1/preview.png)

## Fixed

- **Telemetry floods can no longer exhaust memory.** Game telemetry arrives
  over UDP, which any program on the computer can send to, and every packet
  was queued until the wheel loop caught up. A sender faster than the loop's
  serial writes, such as another local user, could grow that queue without
  limit. Each listener now overwrites a single newest sample, which is all the
  rev lights and vibration ever used, so memory stays constant however many
  packets arrive. This covers every game, including Wreckfest 2 and the
  Codemasters titles, which previously went through a second queue.
  Regression tests flood the Assetto Corsa listener and the shared slot.
  By @crmne; thanks @HANCORE-linux for the report.

## Known limitations

The [0.4.0 notes](https://github.com/crmne/omarchy-moza/releases/tag/v0.4.0)
describe the vibration module, ACC / Le Mans Ultimate helper and game
limitations, which are unchanged. Hardware checks cover an R12 with CS V2P and
the Pedal Haptic Feedback module; ARM64 needs a source build.
