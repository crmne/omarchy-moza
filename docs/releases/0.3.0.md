Pedal setup now keeps live input, guided calibration and range controls
together. Rev lights gain adjustable shift flashes, saved colors and the
current car's actual rev limit in Assetto Corsa.

Download the [Linux x86-64 plugin archive](https://github.com/crmne/omarchy-moza/releases/download/v0.3.0/omarchy-moza-0.3.0.tar.gz).
The bundled executable is built twice in a pinned environment and verified
before publication. The release includes its checksum and build provenance.

## New

- **Calibrate pedals with the input visible.** Each pedal tab starts with
  live input, calibration and range controls, followed by the response curve.
  A three-second preparation countdown and seven-second recording countdown
  guide the process. Missing movement prompts a retry; successful results
  clear after eight seconds. By @crmne.
- **Set an earlier, adjustable shift cue.** The whole strip flashes at 95%
  of the game's reported rev limit by default, independently of the full-light
  threshold. Choose the threshold and a rate from 1 to 20 flashes per second,
  with 10 as the default. The panel shows the cue's RPM for the current car.
  By @crmne.
- **Follow Assetto Corsa's actual engine limits.** The updated
  [Assetto Corsa setup](https://github.com/crmne/assetto-corsa-setup) installs a
  CSP companion that supplies RPM, idle RPM and the current car's limiter.
  Low-revving cars work without a fixed RPM floor. By @crmne.
- **Keep your rev-light colors.** Modern wheels use saved green, yellow and
  red defaults, custom RGB colors and adjustable brightness. Reconnecting,
  testing the strip or reading the wheel's static settings preserves them.
  By @crmne.

## Fixed

- **Expand a previously shortened pedal maximum.** Home reopens the full
  range before capturing a new minimum or maximum, so clipped input cannot
  trap the next adjustment at the old limit. Save changes only the selected
  limit; Cancel or timeout restores the previous limits. By @crmne.
- **Rev lights no longer revert to white or pale colors.** The live palette
  is kept separate from the wheel's static color settings. By @crmne.
- **Malformed telemetry cannot crash the engine through a zero redline.**
  Non-positive redlines produce no rev lights, with regression coverage for
  the reported boundary. By @crmne; thanks @HANCORE-linux for reporting it in
  [marketplace review #11704](https://github.com/omacom/omarchy-plugin-marketplace/issues/11704)
  and [#11990](https://github.com/omacom/omarchy-plugin-marketplace/issues/11990).
- **Panel controls resolve the active theme correctly.** Color references
  use the shell's theme namespace consistently. By @crmne.

## Known limitations

- Assetto Corsa needs the updated setup script's CSP companion. Run setup
  with the game closed. The old legacy UDP feed did not report a rev limit;
  without the companion or a valid limiter, its rev lights stay off.
- Shift flashes use a percentage of the rev limit, not a calculated optimum
  power-band shift point.
- After pedal calibration, check that released input reads 0% and fully
  pressed input reads 100%. The recording result is not a firmware
  acknowledgement. Cancelling after recording begins cannot undo sensor
  calibration.
- Hardware checks cover an R12 with CS V2P, not every supported model. Custom
  live colors require a modern wheel protocol. ARM64 needs a source build.
